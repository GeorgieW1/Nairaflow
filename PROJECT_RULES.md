# Project Rules

## Workflow Process

1. **Planning Phase**
   - First think through the problem, read the codebase for relevant files, and write a plan to `tasks/todo.md`
   - Always ask questions if anything is unclear, and NEVER ASSUME
   - The plan should have a list of todo items that you can check off as you complete them

2. **Approval Phase**
   - Before you begin working, check in with me and I will verify the plan

3. **Execution Phase**
   - Begin working on the todo items, marking them as complete as you go
   - Please every step of the way just give me a high level explanation of what changes you made

## Code Principles

4. **Simplicity First**
   - Make every task and code change you do as simple as possible
   - We want to avoid making any massive or complex changes
   - Every change should impact as little code as possible
   - Everything is about simplicity

5. **Security & Production Readiness**
   - Make sure security is tight and always production ready, no matter the circumstance
   - Before coding, always have this perspective of "what would Mark Zuckerberg do in this situation"

6. **Post-Execution Review**
   - After execution, please check through all the code you just wrote and make sure it follows security best practices
   - Make sure there are no sensitive information in the frontend and there are no vulnerabilities that can be exploited
   - Check for crucial files like .env, and also before pushing to GitHub check as well
   - Always check for syntax errors after code completion
   - Please explain the functionality and code you just built out in detail
   - Walk me through what you changed and how it works
   - Act like you're a senior engineer teaching a 16 year old how to code

7. **Documentation**
   - Finally, add a review section to the `tasks/todo.md` file with a summary of the changes you made and any other relevant information
